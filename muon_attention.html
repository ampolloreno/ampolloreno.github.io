Thoughts on Muon and Second Order Optimization

In this note, I want to make one point precise. Muon has a clean matrix-level derivation for linear layers, but transformers are not composed of linear layers alone. Their core attention operator is bilinear in the query and key projections, and that changes the geometry of the relevant update.

For a linear layer \(y = xW\), we can ask what update gives the largest first-order decrease in loss, subject to a natural operator-norm constraint on the update. If \(G = \nabla_W L\), then the steepest descent update under a spectral-norm constraint is the polar factor of the gradient.

\[ \Delta W \propto -\operatorname{Polar}(G) = -UV^\top, \qquad G = U\Sigma V^\top. \]

Muon approximates this polar factor with Newton–Schulz iterations. The appealing part of the construction is that it does not simply rescale an Adam-like update. It answers a different optimization question. Namely, what update gives the largest first-order decrease in loss under an operator-norm budget?

That derivation is correct as far as it goes. The problem is that attention is not controlled by a single matrix, and so the linear-layer argument does not yet identify the right constrained object for a transformer.

Transformers are not just linear layers. They are linear layers plus attention.

And attention is not a single linear map.

For one attention head, \(Q = XW_Q\), \(K = XW_K\), and \(V = XW_V\). The attention logits are \(S = \frac{QK^\top}{\sqrt d} = \frac{XW_QW_K^\top X^\top}{\sqrt d}\).

So the object that directly controls attention is not \(W_Q\) or \(W_K\) separately. It is the bilinear product \(W_QW_K^\top\).

If one orthogonalizes the updates to \(W_Q\) and \(W_K\) independently, one is still applying the linear-layer derivation. But attention does not use \(W_Q\) and \(W_K\) independently. It multiplies them.

For attention, the relevant constraint should therefore be placed on the induced change in \(QK^\top\). The rest of this note works through that point and explains why recent large-scale Muon deployments add explicit QK/logit stabilization.

The empirical clue

This distinction is not merely formal. Recent large-scale reports already indicate that some additional control is needed around attention.

Moonshot’s Muon scaling report identifies two crucial fixes for scaling Muon, weight decay and per-matrix update-RMS rescaling. It also notes that Muon’s update RMS depends on matrix shape, which can become problematic for small attention matrices such as per-head KV matrices in GQA/MLA-style attention. In their training dynamics, the maximum attention logit can rise above 100 in some layers, even when loss and gradient norm remain stable. [Liu et al., 2025]

Kimi K2 goes further and introduces MuonClip, whose main new ingredient is QK-Clip. The paper says QK-Clip rescales query and key projection weights after the optimizer step to explicitly constrain attention logits. This is a very direct signal. Muon is useful, but Muon plus attention needs an additional QK/logit constraint. [Kimi Team, 2025]

DeepSeek-V4 takes the architectural route. It uses Muon for most matrix parameters, but applies RMSNorm to attention queries and compressed KV entries immediately before core attention. The paper says this avoids exploding attention logits and is why DeepSeek-V4 does not use QK-Clip. [DeepSeek-AI, 2026]

So the emerging pattern is simple. Muon works well for matrices, but attention requires extra QK/logit geometry.

My claim is that this is not a hack. It is exactly what you should expect if the Muon derivation was only done for linear layers.

Do the Muon derivation again, but for attention

For a linear layer, the idealized Muon problem is

\[ \min_{\Delta W}\; \langle G, \Delta W \rangle \quad\text{s.t.}\quad \|\Delta W\|_2 \le \rho. \]

For attention, the analogous constraint should not be on \(\Delta W_Q\) and \(\Delta W_K\) separately. It should be on the induced change in the attention logits.

For one head, \(S = \frac{QK^\top}{\sqrt d}\). A first-order perturbation gives

\[ \Delta S = \frac{(X\Delta W_Q)K^\top + Q(X\Delta W_K)^\top}{\sqrt d}. \]

So the attention-aware Muon problem is

\[ \min_{\Delta W_Q,\Delta W_K} \langle G_Q,\Delta W_Q\rangle + \langle G_K,\Delta W_K\rangle \]

subject to

\[ \left\| \frac{(X\Delta W_Q)K^\top + Q(X\Delta W_K)^\top}{\sqrt d} \right\| \le \rho. \]

This is the formal answer.

If we write \(\theta=(W_Q,W_K)\), \(g=\nabla_\theta L\), and \(J_S\) for the Jacobian mapping parameter updates to logit updates, then the exact trust-region update has the natural-gradient/Gauss–Newton form

\[ \Delta\theta^* = -\rho\, \frac{(J_S^\top J_S + \lambda I)^{-1}g} {\sqrt{g^\top (J_S^\top J_S + \lambda I)^{-1}g}}. \]

This is the attention analogue of the Muon derivation.

The important point is that \(W_Q\) and \(W_K\) are now coupled. The optimizer is not allowed to say, “this is a good update to \(W_Q\)” and “this is a good update to \(W_K\)” independently. It has to ask whether the pair of updates causes a reasonable change in \(QK^\top\). That is the missing geometry.

Why not just do this in the optimizer?

Because it is much less convenient than ordinary Muon.

Muon is cheap because it is local to one matrix. You take a matrix-shaped momentum buffer, run a few Newton–Schulz iterations, rescale the update, and apply it. This is simple enough that large-scale implementations can make it practical.

The attention-aware update is not local to one matrix. It depends on the current activations \(X\), the current queries \(Q\), the current keys \(K\), the attention mask, the head structure, the sequence length, the softmax geometry, and in modern models compressed, sparse, latent, grouped, or multi-query attention layouts.

Even before considering the softmax, the natural object is the logit matrix \(S\), which is sequence-by-sequence. In dense attention this is \(T \times T\) per head. In sparse or compressed attention, it becomes architecture-specific. In MLA-style or compressed-KV attention, the key may not even be materialized in the same way at training and inference.

So the exact optimizer-side solution is mathematically clear but operationally ugly. The right Q/K update is a coupled logit-space trust-region update.

The practical question is whether we can impose the same constraint somewhere cheaper.

Yes. Put it in the architecture.

QK normalization is the architectural version of the missing optimizer

The scalar attention logit is \(\ell(q,k) = \frac{q^\top k}{\sqrt d}\).

The dangerous degrees of freedom are the radial norms of \(q\) and \(k\). If Muon updates \(W_Q\) and \(W_K\) independently, the product \(QK^\top\) can grow even when the individual matrix updates look reasonable.

A direct architectural fix is to set \(\hat q = R_q \frac{q}{\|q\|_2 + \epsilon}\) and \(\hat k = R_k \frac{k}{\|k\|_2 + \epsilon}\), and then compute \(\ell(q,k)=\frac{\hat q^\top \hat k}{\sqrt d}\). In transformer notation this becomes \(\hat Q_h = \operatorname{RMSNorm}(Q_h)\) and \(\hat K_h = \operatorname{RMSNorm}(K_h)\), followed by \(S_h = \alpha_h\frac{\hat Q_h\hat K_h^\top}{\sqrt d}\).

The scalar \(\alpha_h\) is the attention-temperature or radius budget. The clean theoretical version uses one scalar per head. A full RMSNorm gamma vector is a learned diagonal metric; it may be useful in practice, but it is less isotropic than the pure Euclidean story.

Now the logits are bounded. In particular, \(|\ell(q,k)| \le \frac{\|\hat q\|_2\|\hat k\|_2}{\sqrt d} = \frac{R_qR_k}{\sqrt d}\). Even more importantly, the local sensitivity is bounded. Here \(\nabla_{\hat q}\ell = \frac{\hat k}{\sqrt d}\) and \(\nabla_{\hat k}\ell = \frac{\hat q}{\sqrt d}\), so \(\|\nabla_{\hat q}\ell\|_2 = \frac{R_k}{\sqrt d}\) and \(\|\nabla_{\hat k}\ell\|_2 = \frac{R_q}{\sqrt d}\).

This is exactly the kind of operator-norm control that the Muon story was trying to provide.

The Jacobian view

For intuition, replace RMSNorm with exact L2 normalization and write \(\hat q = R\frac{q}{\|q\|_2}\). Let \(u = \frac{q}{\|q\|_2}\). Then

\[ D\hat q = \frac{R}{\|q\|_2} \left(I - uu^\top\right). \]

The term \(I - uu^\top\) is the projection onto the tangent space of the sphere. QK norm removes the radial direction. An update that merely increases \(\|q\|\) does not change the attention logits.

This is the sense in which QK norm is doing optimizer work in the architecture. The optimizer no longer has to learn not to spend update budget on radial Q/K growth, because the forward pass has made that direction mostly irrelevant.

So the equivalence is roughly the following. Attention-aware Muon approximately projects the optimizer step onto safe logit geometry, while QK norm reparameterizes attention so that the unsafe radial directions disappear.

This is why DeepSeek-V4’s solution is so clean. They did not make Muon itself attention-aware. They made the attention interface Muon-safe.

Which normalization should this predict?

People use a variety of attention stabilizers, including QK norm, RMSNorm, L2 normalization, L1-ish normalization, tanh softcapping, arctan softcapping, and explicit logit clipping.

The Muon-derived answer is not arbitrary.

If the premise is “extend Muon’s linear-layer argument to attention,” then the compatible normalization is per-head L2/RMS QK normalization.

Why?

Muon’s motivating geometry is spectral norm. Spectral norm is the operator norm induced by Euclidean vector norms, namely \(\|W\|_2 = \sup_{\|x\|_2=1}\|Wx\|_2\).

The vector geometry paired with this is \(\ell_2\).

Equivalently, to bound the dot product, Holder’s inequality gives \(|q^\top k| \le \|q\|_p\|k\|_{p^*}\) with \(\frac1p + \frac1{p^*}=1\). The only symmetric self-dual choice is \(p=2\).

It is also the only rotation-invariant choice. That matters because Muon’s polar update is built from SVD/orthogonal geometry. An \(\ell_1\) or \(\ell_\infty\) constraint picks out coordinate axes. It is not the same geometry.

So the clean prediction is to use per-head RMS/L2 normalization on Q and K before the dot product. RMSNorm is just L2 normalization written in the usual transformer scale, since \(\operatorname{RMS}(q)=\frac{\|q\|_2}{\sqrt d}\).

Why scalar logit softcaps are different

A scalar cap such as \(\ell \mapsto \tau\tanh(\ell/\tau)\) or \(\ell \mapsto \tau\arctan(\ell/\tau)\) bounds the logit value after the dot product.

That can be useful. But it is not the same constraint.

If \(c(\ell)\) is the scalar cap, then \(\nabla_q c(\ell) = c'(\ell)\frac{k}{\sqrt d}\).

Near \(\ell=0\), most softcaps have \(c'(0)\approx 1\). Therefore, if \(k\) has huge norm but happens to be nearly orthogonal to \(q\), the scalar logit is small while the local sensitivity can still be huge.

A softcap controls values. QK norm controls the operator.

Under the Muon/operator-norm story, QK RMSNorm is the more principled architectural answer. A scalar cap can still be useful as a guardrail, but it is not the same thing as fixing the missing QK geometry.

QK-Clip, attention-aware Muon, and QK norm are the same idea in three places

These mechanisms can be understood as the same constraint imposed at three different points in the stack.

  • QK-Clip projects the state after the optimizer step.
  • Attention-aware Muon projects the optimizer step in logit space.
  • QK norm changes the architecture so the bad direction disappears.

Kimi K2 uses the first route. It lets Muon update the matrices, then rescales Q/K weights if the resulting attention logits become too large. [Kimi Team, 2025]

The formal optimizer derivation gives the second route. It says that the Q/K update should be chosen under a trust region on \(\Delta(QK^\top)\).

DeepSeek-V4 uses the third route. It directly normalizes queries and compressed KV entries before attention, and therefore does not need QK-Clip. [DeepSeek-AI, 2026]

This makes QK norm look much less like an ad hoc fix. It is the architectural form of the norm constraint that the optimizer derivation forgot to impose.

Equivalently, QK norm is the missing Muon derivation for attention, moved into the forward pass.

Where mHC fits, and where it does not

DeepSeek-V4 also uses manifold-constrained hyper-connections, or mHC. That is a different stabilization story.

mHC expands the residual stream and learns pre-, post-, and residual mixing maps, but constrains the residual mixing matrix to be doubly stochastic. The point is that doubly stochastic residual maps are non-expansive and closed under composition, so repeated residual mixing does not blow up or vanish across depth. [Xie et al., 2026]

That is a macro-architecture constraint on residual signal propagation.

QK norm is a micro-architecture constraint on attention-logit geometry.

They are complementary. mHC controls residual routing, while QK norm controls attention logits.

Neither one is a generic substitute for the other.

What this says about AdamW, Muon, and second-order optimization

A separate question is when you should use Muon at all.

In practice this still has to be checked empirically, but there is a useful organizing principle.

AdamW became standard because it combines a few things that are easy to want.

  1. momentum,
  2. diagonal adaptive scaling,
  3. decoupled weight decay,
  4. good default behavior across many workloads.

You can interpret Adam-style adaptive scaling as a cheap diagonal approximation to second-order geometry. It is not a full Hessian inverse, but it tries to rescale coordinates using local gradient statistics.

Muon is a different kind of cheap geometry. It does not estimate a full Hessian either. Instead, it uses matrix structure. The polar update has controlled spectral norm, and its singular spectrum is much flatter than a raw gradient update. So instead of diagonal coordinate-wise adaptation, Muon gives a matrix-level operator-norm update.

That is why Muon is appealing if you like maximal-update or hyperparameter-transfer arguments. It pushes some of the “make the update the right size” logic into the optimizer. Shah et al. explicitly study Muon together with maximal update parameterization and find that Muon expands the compute-time Pareto frontier over AdamW, while retaining data efficiency at large batch sizes. [Shah et al., 2025]

Moonshot’s Muon report makes a similar practical claim. After adding weight decay and correcting update RMS, their scaling-law experiments show roughly a 2x compute-efficiency improvement over AdamW under their compute-optimal setup. [Liu et al., 2025]

But the attention story says that matrix-level maximal updates are not enough. For MLP matrices, the matrix is the operator. For attention Q/K, the operator is the product.

So the right principle is simple. Use Muon where the parameter is the operator. Add QK geometry where the operator is bilinear.

Does a second-order optimizer change the critical batch size story?

It should, but not in the naive way.

The first-order critical batch size story starts from a local quadratic model with stochastic gradients. The expected progress per step has the familiar diminishing-returns form

\[ \Delta L_{\mathrm{opt}}(B) = \frac{\Delta L_{\max}}{1+B_{\mathrm{noise}}/B}. \]

The noise scale predicts the point where increasing batch size gives diminishing returns.

If we add a fixed deterministic preconditioner \(P\), the same calculation gives a modified critical batch size

\[ B_P = \frac{\operatorname{tr}(HP\Sigma P)}{g^\top P H P g}. \]

For Newton or natural-gradient style preconditioning with \(P=H^{-1}\), this becomes

\[ B_N = \frac{\operatorname{tr}(H^{-1}\Sigma)}{g^\top H^{-1}g}. \]

So even before stochastic curvature estimation, preconditioning changes the noise metric. The relevant gradient noise is now whitened by curvature.

If the curvature itself is estimated stochastically, there is a second statistical problem. The update is no longer just \(H^{-1}\hat g\). It is \(\hat H^{-1}\hat g\).

That creates two noise scales. One is a gradient-side scale and the other is a curvature-side scale. In the notation of my note,

\[ B_g = \frac{\operatorname{tr}(H^{-1}\Sigma_g)}{g^\top H^{-1}g}, \]

and

\[ B_h = \frac{u^\top \mathbb E[\delta H^{-1}\delta]u}{g^\top H^{-1}g}, \qquad u=H^{-1}g. \]

The second-order progress law is approximately

\[ \frac{\Delta L_{\mathrm{opt}}(B_1,B_2)}{\Delta L^N_{\max}} \approx \frac{1}{1+B_g/B_1+B_h/B_2}. \]

So second-order optimization has a critical surface, not a single critical batch size.

\[ \frac{B_g}{B_1}+\frac{B_h}{B_2}\approx 1. \]

That is the clean theoretical answer to the question “does the batch size story change for second-order methods?” Yes. There is now a gradient batch and a curvature batch.

But practical Muon is not full stochastic Newton. It does not draw a separate curvature minibatch and invert it. It uses a strong structural prior. The update should be matrix-orthogonalized. It also uses temporal averaging through momentum.

If an estimator is exponentially averaged as \(s_t=(1-\beta)x_t+\beta s_{t-1}\), then under stationarity its variance is reduced by \(\frac{1-\beta}{1+\beta}\). The effective sample multiplier is therefore \(M_\beta = \frac{1+\beta}{1-\beta}\). For \(\beta=0.95\), \(M_\beta \approx 39\). For \(\beta=0.99\), \(M_\beta \approx 199\).

This is why matrix-whitening optimizers can behave more second-order without requiring a huge separate curvature batch. They combine structure and averaging.

The important conclusion is not “Muon needs a much larger batch.” Second-order-ish optimizers change the statistical estimation problem.

For full curvature, the curvature-side batch can be enormous. For structured or factorized curvature, it can be much smaller. In the critical-curvature note, full outer-product curvature has \(B_h=d+1\) in a whitened Gaussian block, while a K-FAC block of shape \(n\times m\) has

\[ B_h^{\mathrm{KFAC}} \approx n+m+2. \]

That is the same lesson as Muon in a different language. Structure matters. You do not get scalable second-order behavior by estimating a giant dense curvature matrix. You get it by choosing a structured geometry that has a much smaller statistical burden.

This also explains why the batch-size story can coexist with the empirical Muon story. Public dense training batches are still largely governed by the gradient-side critical batch and hardware utilization. The second-order side can be kept under control by structure, momentum, and update-scale normalization.

MoE and the batch-size caveat

MoE models seem to favor larger token batches in public training runs. I do not know of a clean microscopic theory for this that is as satisfying as the first-order critical batch story.

Empirically, however, public MoE operating points look closer to the dense-model power-law band when indexed by total parameters rather than activated parameters, with an architecture-dependent coefficient shift. In the critical-curvature note, the public MoE points are described as roughly compatible with the same first-order exponent on total parameters but with an upward coefficient shift relative to dense models.

That is a useful practical rule, not a derived law.

So my current view is the following.

  1. Use critical-batch experiments at small scale to estimate the gradient-side batch schedule.
  2. Expect architecture-dependent shifts, especially for MoE.
  3. Do not assume Muon requires a fundamentally larger global batch just because it is second-order-ish.
  4. But do recognize that Muon introduces a different statistical estimation problem, matrix-level update geometry plus temporal averaging, rather than purely diagonal moment estimation.

A small eigenvalue/spectral-norm sanity check

There is also a simple stability reason to like Muon.

For a linear layer, if the Muon update is exactly polar-normalized, then \(\|\operatorname{Polar}(G)\|_2 = 1\). So the operator norm of the raw update is controlled, with \(\|\Delta W\|_2 \le \eta\rho\).

This does not prove that training is globally stable. But it does say that the per-step perturbation of the layer as an operator is bounded in the geometry that the layer actually uses.

For attention, the analogous bound would be on \(\Delta(W_QW_K^\top)\). Using first-order expansion,

\[ \Delta(W_QW_K^\top) \approx \Delta W_Q W_K^\top + W_Q\Delta W_K^\top. \]

Independent bounds on \(\Delta W_Q\) and \(\Delta W_K\) do not directly bound the product in the same clean way unless we also control the norms of \(W_Q\) and \(W_K\) or normalize the resulting queries and keys.

Again, QK norm is exactly the architecture-side fix. If \(q,k \mapsto \hat q,\hat k\), then \(|\hat q^\top\hat k| \le \|\hat q\|_2\|\hat k\|_2\).

The spectral story and the attention story match.

The practical recipe

If I were specifying a Muon transformer from this argument, I would do the following.

Use Muon for matrix parameters whose forward role is actually linear. That includes MLP matrices, expert matrices, dense projections, router matrices, and perhaps attention value/output matrices.

For Q/K, do not rely on independent per-matrix Muon alone. Use per-head QK RMSNorm before the attention dot product, preferably with a scalar learned temperature per head if you want the cleanest geometry.

Use QK-Clip as a diagnostic or guardrail when architectural QK normalization is unavailable or awkward. This is especially relevant for attention variants where keys are compressed, latent, or not fully materialized.

Log the quantities that correspond to the theory. That includes max attention logit, RMS attention logit, large-logit ratio, query/key RMS, update RMS by matrix shape, and loss/gradient spikes.

Estimate critical batch size at small scale for the actual optimizer and architecture, not just for SGD. The first-order scale gives the main training batch. The second-order or matrix-whitening side is controlled by structure, momentum, and update-scale choices.

Conclusion

Muon is a principled matrix update rule, but the standard derivation is a derivation for linear operators.

In transformers, attention depends on the bilinear logit operator \(QK^\top\). If Muon is applied independently to \(W_Q\) and \(W_K\), then the matrix-level constraint does not by itself control the object that attention actually uses.

This is consistent with what recent systems report in practice. Moonshot observes attention-logit growth and corrects Muon’s scaling behavior. Kimi K2 adds QK-Clip. DeepSeek-V4 normalizes queries and compressed KV entries before attention and therefore avoids QK-Clip.

The clean interpretation is straightforward. QK norm is not a hack. It is the missing attention-aware Muon constraint, moved into the architecture.

The broader optimizer story is similar. AdamW is a cheap diagonal geometry. Muon is a cheap matrix geometry. Second-order critical-batch theory says that changing geometry changes the noise scale, and stochastic curvature introduces a second noise scale. But practical matrix optimizers avoid huge curvature batches by using structure and temporal averaging.

The practical prescription is straightforward. Use Muon where the parameter itself is the operator, keep update RMS and weight decay under control, and treat attention separately by imposing QK geometry explicitly, ideally through per-head RMS/L2 normalization. That is the point at which the Muon story becomes substantially more complete.
